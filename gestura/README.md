# 手迹 · gestura

> 手即笔。不靠鼠标，不靠按钮——摄像头追踪 21 个手部关键点，手的动作本身就是笔画。

一个**实时**的手势绘画装置：摄像头进，画面出，中间没有录制和回放。**食指伸出即落墨**，蜷起抬笔；移动手画线，慢则粗快则细，手张得越开笔画越饱满。

Phase 2 已完成：手势定桩（拇指指向八方位长出结构）+ 双手对位场（镜像 / 吸引 / 排斥）。

---

## 快速开始

```bash
cd gestura
python serve.py 8000        # 打开 http://127.0.0.1:8000，点「开启摄像头」
npm test                    # 311 项断言，Node 直跑，无需浏览器
```

**用 `serve.py` 而不是 `python -m http.server`。** 后者只发 `Last-Modified` 不发 `Cache-Control`，浏览器会用修改时间做启发式缓存；而这个项目的开发循环就是「改文件 → 刷新」，于是每次改动都变成一次硬刷新赌运气，过期模块报出的还是 `tracker.warmUp is not a function` 这种完全看不出所以然的错。

**必须走 `localhost` 或 https**：`getUserMedia` 只在安全上下文可用，`file://` 会被直接拒绝。用桌面版 Chrome / Edge 体验最佳。

无 `npm install`，无构建步骤。`package.json` 只是给 `npm test` 一个入口。模型和 WASM 走 CDN，`importmap` 里一行换版本。

## 输入模型：位置、速度、食指

传统绘画只有「位置」一个输入。gestura 手上每一点是三元组：

| 量 | 来源 | 作用 |
| --- | --- | --- |
| **位置** | 食指尖 `LM 8` | 笔画走向 |
| **速度** | 位置一阶差分 | 笔触粗细 + 干湿程度 |
| **食指伸展** | 食指尖→腕 ÷ 食指 PIP→腕 | 抬笔 / 落墨 |
| **五指开合** | 五指尖 / 近节 指距比 | 笔宽饱满度 |

### 速度 → 笔宽

```
t     = smoothstep(clamp(speed / vRef, 0, 1))
width = lerp(maxW, minW, t^0.72) × lerp(0.45, 1, press)
```

`^0.72` 让过渡偏早——真毛笔在快速段一开始就明显提细，不是到末尾才细。

差分必须**按 dt 归一化**，否则 30fps 和 60fps 下同一次挥手算出两倍笔速，笔宽会跟着帧率漂。

### 食指伸展 → 抬落笔

```
ratio = dist(食指尖, 腕) / dist(食指 PIP, 腕)     // 伸直 ~1.9，蜷起 ~1.0
落笔:  ratio > 1.18      抬笔: ratio ≤ 1.10
```

**落墨看的是食指，不是整只手张开程度。** 早期版本用 `openness` 同时决定落墨和笔宽，结果最自然的写字姿态——食指伸出、其余三指蜷起——`openness` 只有 0.18，被判成抬笔，什么都不画。这是个实测出来的设计错误，所有同类项目用的都是「食指伸出 = 画」。

两个阈值之间留了**迟滞窗口**：单阈值会让手指在边界抖动，笔画上出现一串散点（测试 `mid-gesture does not chatter`）。

除以 PIP 距离是为了**尺度无关**：手离摄像头远近变化时比值不变。测试 `ratio identical at 0.45x and 1.8x` 守的是这条。

### 五指开合 → 笔宽饱满度

```
openness = clamp((mean(指尖→腕) / mean(近节→腕) - 1.0) / 0.85, 0, 1)
press    = clamp(openness / 0.5, 0, 1)          // 只影响粗细，不再决定落墨
```

单指写字时 `openness` 约 0.18 → 笔画略细；张掌时 0.65 → 饱满。下限刻意不压到 0，否则单指写出来的是发丝线。

### 抬笔时不连线

抬笔时置 `pending`，下次落墨**不从旧位置连线**，否则手移开再落下会拉一条横贯画布的直线。

### 平滑：One-Euro，不是固定速率

指数平滑要在「去抖」和「不滞后」之间二选一，固定系数只能取一个折中值。One-Euro 滤波（Casiez et al., CHI 2012）按实测速度自适应调节截止频率。800px/s 匀速扫过的实测对比：

| | 峰值滞后 | 平均误差 | 静止抖动 |
| --- | --- | --- | --- |
| 固定速率 12/s | 55.1px | 52.8px | 1.96px |
| One-Euro | **8.8px** | **6.4px** | **0.68px** |

滞后差 6 倍，抖动还更小。

### 位置重采样：30Hz 检测 vs 150fps 渲染

检测只在摄像头出新帧时跑（通常 30/s），而页面渲染远快于此。直接用检测坐标会让笔**以 30 次/秒阶梯式跳动**，渲染再高都没用——这才是「感觉卡」的真凶。

所以按渲染率重采样：在两次检测之间插值，并允许**有上限的**轻微外推（上限是必须的，否则检测一停笔就会被甩飞）。实测 30Hz 检测下，笔画 99.2% 的渲染帧都拿到新位置。

## 四种笔性

`NIBS` 表里每种笔性是一组数字，**不是四份代码**：

```js
silk    { maxW 26, minW 1.1, dry 0,   bleed 0, hairs 0, splatter 0,    glow .55 }
flying  { maxW 30, minW 9,   dry .9,  bleed 0, hairs 9, splatter .25,  glow .10 }
splash  { maxW 42, minW 2.2, dry 0,   bleed 0, hairs 0, splatter 1,    glow .32 }
rubbing { maxW 28, minW 7,   dry .25, bleed 1, hairs 0, splatter 0,    glow .08 }
```

| 笔性 | 手感 | 实现 |
| --- | --- | --- |
| **丝绢** | 快慢都是连绵的 | 变宽 ribbon + 加色辉光拖尾 |
| **飞白** | **要快** | 笔宽几乎不掉，笔毛分离成 9 束，束间留白即飞白 |
| **泼墨** | **要甩** | 抛物线抛出次级墨滴，落地行为见下 |
| **拓印** | **要慢** | 顶点吸附 19px 格点画硬边八边形 + 印泥晕开 |

### 飞白：为什么 `minW` 是 9

干笔不是「变细的笔」，是**保持了宽度但散开的笔**。所以 `flying.minW = 9` 而不是接近 0——笔始终是宽的，散开的是笔毛。

干湿与速度耦合：`dryness = nib.dry × smoothstep(speed / vRef)`。慢速时 `dryness = 0`，笔画仍实心，加速后才撕开。

**散开是连续的，不闪。** 每支笔毛有固定槽位（`slot`）和固定脱落序（`bias`），存活判据：

```js
hash01(bias × 91.7 + chunk × 13.31 + slot × 57.13) <= 1 - dryness
```

`bias` 单调递增 → 提速时笔毛按固定顺序脱落。屏幕空间哈希 `chunk` 把留白切碎成不规则段，所以是锯齿状而非规则条纹。

关键在**笔毛只分配一次**（`splayHairs`，存在笔 state 上）。每帧重新随机会让缝隙乱爬，看起来是噪点而不是飞白。

### 拓印：印泥晕开

格点吸附带 ±1.4px 抖动，否则会呈现机械的完美网格，看起来像贴图而不像盖章。晕开画在 `ink` 层而非淡出的 `glow` 层——渗进纸纤维的墨必须比造成它的笔活得久。

### 泼墨：墨滴与纸面碰撞

| 落点 | 行为 |
| --- | --- |
| 湿墨（`wetness > 0.15`） | 沿速度方向压扁成 0.34 比例的横向涂抹，向外**推高湿度**，半衰加快 → 墨从湿处向外洇 |
| 干纸 | 只留一个小点 |
| 飞行中 | 高速时断成断续圆点拖痕 |
| 出界 | 落定后按 `decay` 淡出 |

`contact` 控制反应强度：`splash = 1`、`flying = 0.5`、`silk = 0`。

## 湿度场 Wetness

墨滴要能分辨湿墨和干纸，而**逐滴逐帧回读 ink 画布像素太慢**。所以湿度是 20px 粒度的占用场：

```js
at(x, y)          // 查询
mark(x, y, r, a)  // 取 max，不是平均
dry(dt, 0.6)      // 指数衰减，低于 1e-3 归零
```

`mark` 取 max 是因为**墨只会叠加不会稀释**；`dry` 让湿墨在两三秒内变干，所以墨滴不会被同一片永久水洼反复触发。

## 双层画布

| 层 | 生命周期 | 作用 |
| --- | --- | --- |
| `ink` | 永久累积 | 所有笔画 + 墨滴 + 晕开 + 结构，`clear()` 才清 |
| `glow` | 每帧 `destination-out` 淡出 | 笔头辉光，`lighter` 叠加 |

分两层的原因：**静止时墨要积聚**。同一层里做淡出会把停笔处的墨一起擦掉，而单层画不出笔头那种湿润的光。用 `destination-out` 而非画背景色，是为了让 `lighter` 叠加不受背景污染。

DPR 上限锁 2：Canvas 是 CPU 光栅化，3x 屏上每帧多填一层全屏四倍像素不值得。

# Phase 2：手势定桩

## 八方位

手比不出八个数字，所以定桩用**拇指指向的方位**而不是手指数：

```text
              ↑ 晶格 lattice
    波纹 ↖          ↗ 分形 fractal
网格 ←    掌   → 放射 radial
    星芒 ↙          ↘ 双螺旋 helix
              ↓ 环 rings
```

八个扇区各 45°，从屏幕正上方顺时针。**扇区的 `id` 直接就是生成器的函数名**（`lattice` / `fractal` / …），提交后不需要查找表就能落到对应生成器上。

### 指向姿态

```js
isPointing = 四指全蜷 && 拇指伸出
```

四指蜷缩判据是「指尖到腕比自己的 PIP 到腕近」；拇指却判它**到小指 MCP** 的距离——因为拇指侧向伸展时指尖到腕的距离几乎不变，用腕距比会把伸直的拇指读成蜷缩的。

**这个姿态天然抬笔**（食指数值 1.00，低于落笔阈值 1.18），所以定桩时不会同时在原地抹一道墨。测试 `pointing does not write` 守的是这条 —— 抬笔判据和定桩姿态判据用的是**同一套信号**，两者天然互斥，不需要额外互斥逻辑。

### 保持判定

一次手势是「在同一个扇区里不动」，不是「当前在某个扇区」：

```js
if (!pointing || |angle - heldAngle| > HOLD_SLOP_DEG) 重新计时
progress = (now - since) / HOLD_MS      // HOLD_MS = 700, HOLD_SLOP_DEG = 26
```

容差窗口是必要的：指向 40° 的手仍然指向分形（22.5–67.5），不能因为追踪噪声把它推过 22.5 边界就重新计时。

`ready` 在满足条件的那一次调用里翻 true 一次，所以一次保持只提交一次。

## 八种结构

全部**种子化生成**（`mulberry32`），同一个手势永远长出同一形状——用 `Math.random()` 的话，同一个姿态每次重放都是不同的画。

| 方位 | 结构 | 生成方式 |
| --- | --- | --- |
| ↑ | **晶格** | 六/十/十四/十八点的错位环，环间距随半径变疏 |
| ↗ | **分形** | 三层递归分叉，张角逐层收窄（0.62 → 0.34 rad） |
| → | **放射** | 14 条射线，长度由低频正弦波驱动，带弯折 |
| ↘ | **双螺旋** | 两条反向旋臂 2.15 圈，按 1/9 概率连横档 |
| ↓ | **环** | 5 圈多边形，每圈随机边数、随机缺口 |
| ↙ | **星芒** | 5 根带倒刺的长刺，刺长随位置递减 |
| ← | **网格** | 16 点不规则三角剖分，**丢弃长边**让格子保持开敞 |
| ↖ | **波纹** | 7 圈相位错开的涟漪，波瓣数 3–6 |

每种结构 47–897 个点，`GROW_MS = 900` 内长完，然后永久留在画布里。`STAKE_LIMIT = 24`，超出时丢最旧的。

`grid` 吸附到格点但顶点带 ±1.4px 抖动；`mesh` 丢弃长边——两者都是为了避免「完美」看起来像贴图。

### resize 时的结构

笔画活在与设备像素绑定的空间里，没有点缓冲可以缩放，所以**resize 会清掉笔画**。但结构是生成出来的几何，可以按视口比例重新锚定并整株重绘：

```js
s.x *= w / oldW;  s.y *= h / oldH;  s.scale *= min(sx, sy);  s.grown = 1;
```

# Phase 2：双手对位场

两只手都落墨且相距超过 `MIN_SEPARATION = 90` 时场才生效，四种模式：

| 模式 | 作用 |
| --- | --- |
| 无场 | 不干预 |
| 镜像 | 关于**画布竖直中线**反射，y 不变 |
| 吸引 | 沿分离向量向中点拉，拉力随分离增长，封顶 `ATTRACT_MAX = 110` |
| 排斥 | 沿分离向量推开，封顶 `REPEL_MAX = 260`，并夹在视口内 |

**镜像必须关于画布中线，不是关于两手中点。** 关于两手中点反射会把每支笔送到另一支笔所在的位置——两笔互相覆盖，而不是生成对称图形。

**吸引必须有上限**，否则两手会穿过彼此、图形从内部翻出来。

**排斥要夹在视口内**，否则一次猛推会把墨甩到屏幕外，再也看不到。

### 场只作用于落墨的笔

`down` 要求 `press > 0.3`。举起双手时场依然在跑（可以在骨架窗里看到），但不会画——否则你举起双手观察场形时会顺手抹一道墨。

### 缓动而非开关

场在 7/s 内升起、11/s 内落下（落下比升起快，避免残影）。追踪掉一帧时场不会瞬间消失把画糊掉。

### 每支笔被**另一支**变形

不是一支追固定锚点——两支笔各自朝对方移动，图形才会对称呼应。

## 身份追踪

MediaPipe 的 `landmarks` 数组顺序不保证稳定，双手交叉时会交换。所以手身份自己管：

```
同 handedness + 腕点距离 < 0.34（归一化） → 复用同一 id
否则                                      → 新建 id
```

丢失超过 12 帧丢弃该手的 state——否则手从画面外回来会从旧位置拉一条线。

`seen === false` 的帧**完全不落笔**也不更新位置：快速运动时追踪会短暂丢帧，按上一帧位置补一笔会画出折角。

### 为什么 `pose.js` 和 `hands.js` 分开

`hands.js` 顶部 import MediaPipe，所以在 Node 里 import 它就会去加载 WASM。把纯几何（食指伸展、开合度、指向姿态、掌心、骨架边表）拆到 `pose.js`，那些姿态规则就能对着合成手型跑，不需要浏览器也不需要模型文件。

`test/stubs/tasks-vision.js` 是一个最小的 MediaPipe 替身，测试启动时把它写进 `node_modules/`（已 gitignore），于是 `hands.js` 也能在 Node 里跑。**这个拆分是有代价的**：`hands.js` 曾是唯一零覆盖的模块，而一个 `export ... from` 不绑定本地作用域的 bug 就藏在那里，只在检出手时触发，表现成「手一出现就卡死」。补上覆盖后这类错误不会再逃逸。

### 快捷键

| 键 | 作用 |
| --- | --- |
| `1`–`4` | 丝绢 / 飞白 / 泼墨 / 拓印 |
| `V` | 切换双手场（无场 → 镜像 → 吸引 → 排斥） |

| `H` | 隐藏 / 显示面板 |

### 出问题时看哪里

预览窗下方那三行就是全部状态，不必去翻控制台：

```
1280x720 · 30/s · GPU          尺寸 / 检测帧率 / 后端
模型返回 2 手 · 推理 6ms       模型的原始输出
已检出手                       或：模型未检出手 / 失败×N: <消息>
```

还有「复制诊断」按钮，一键把尺寸、后端、失败计数、画布状态、UA 全部复制到剪贴板。浏览器标签标题在出错时会变成 `⚠ <消息>` —— 面板可能被截图裁掉，标题不会。

循环本身有护栏：一帧抛异常不会终止 rAF 链，错误会被捕获并显示，而不是让页面静默定格。

## 隐私
